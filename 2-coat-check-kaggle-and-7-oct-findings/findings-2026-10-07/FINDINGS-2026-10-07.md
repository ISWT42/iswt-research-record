## 1. The coat-check removes false "done" on never-ran logs (Kaggle, four models)
- Counts: never-ran logs called "done" after the do sentence (T3, published 2 Oct): Gemini 3.7 Flash 11 of 16, Gemini 3.8 Flash 5, Claude Haiku 4.5 10, GPT-5.4 nano 16. With a coat-check ticket (t6): 0, 0, 0 and 1 of 16 called "shown". Failed checks under the plain report sentence (T1): 7, 5, 0, 0; with the ticket (t5): 0, 0, 0, 0. Mean receipts t6: 1.000, 1.000, 1.000, 0.958.
- Records: forecasts and files sealed 18:11:00 UTC (Workbench/kaggle-coat-check-update-2026-10-07/FILES-SHA256.txt, Bitcoin block 970376); results sealed 20:19:19 (RESULTS-2-SHA256.txt).
- Plain meaning: when the model is handed a ticket written before the work (the check, and what done means) and must quote the line that settles it, the small models stop saying "done" when the check never ran. Limit: the ticket stated the expected value, which makes the question easier. The blind version (ticket names only the check) is sealed and running (Workbench/kaggle-coat-check-blind-2026-10-07).

## 4. Coat-check relay test (four cheap models, 12 coding jobs, 3 repeats)
- Counts, false "done" left at the end, of 36 jobs per arm (the runner ran the hidden tests itself): A self-report 16; B coat-check then the same agent may fix once 7; C a second agent certifies before its own work (and may improve the design) 11; D the second agent works before certifying 9.
- Primary tests (exact McNemar, paired): A against B 9 against 0, p = 0.0039 (shown, Holm over two primaries). A against C 8 against 3, p = 0.23 (not shown). A against D (secondary) 10 against 3, p = 0.09.
- Certifiers: caught 9 of 9 and 7 of 7 false "done" they certified; false assurance 0 of 24 and 0 of 23; false alarms 0 of 11 each; planted records with no check named not shown 7 of 13 and 9 of 14 (never called shown). Yet C ended with more false "done" (11) than it started with (9): the improve step added errors.
- Self-forecasts are badly overconfident: mean stated chance the check passes 0.85 to 1.00 against pass rates 0.31 to 0.74 (Brier 0.21 to 0.53 by model).
- Invalid replies 56 of 280 calls (20%). Cost US$0.118 of the US$1 cap. Wasted work: D 8 of 27 dependent jobs against C 11 of 27.
- Records: design and forecasts sealed 21:29:16 GMT; results sealed 23:45:35; scored 23:46:01 GMT (Workbench/coat-check-relay-2026-10-07/RESULTS-SHA256.txt, SCORED-SHA256.txt). The room's hash chain verifies: 1,987 records.
- Plain meaning: showing an agent the real check result before it can call the job done, and letting it fix once, cut false "done" by more than half (16 to 7 of 36). A second agent reading the record caught every false claim it was shown, but letting that agent rewrite the work undid part of the gain. Certify, yes; certify-and-rewrite, not yet. Limits: one run, 36 pairs, cheap models with a 20% invalid-reply rate, one author wrote the 12 jobs.

- Counts (scenarios of 16, three counted runs each): never-ran logs called "shown" with a ticket that names only the check (t8): Gemini 3.7 Flash 0, Gemini 3.8 Flash 0, Claude Haiku 4.5 0, GPT-5.4 nano 0 (do-the-work prompt T3, published: 11, 5, 10, 16; ticket with the value, t6: 0, 0, 0, 1). Failed checks called "shown" (t7): 0, 0, 0, 0 (plain report T1: 7, 5, 0, 0). Mean receipt score 1.000 for all four models on both blind tasks; no invalid replies.
- Paired against the earlier prompts (exploratory): Gemini 3.7 Flash T3 to t8 11 to 0, p = 0.001; T1 to t7 7 to 0, p = 0.016; GPT-5.4 nano T3 to t8 16 to 0. Blind against value-stating ticket: no difference on any model.
- Records: forecasts and files sealed 20:54:59 GMT (Bitcoin block 970397, confirmed 22:57:25); results sealed 23:47:51 GMT (Workbench/kaggle-coat-check-blind-2026-10-07/RESULTS-SHA256.txt); analysis code matched its seal.
- Plain meaning: the ticket does not need to hand over the answer. Naming the check before the work, and requiring the line that settles it at pickup, took false "done" to zero on all four small models. Limits: the job sentence still states the target in 10 of the 16 jobs (the never-ran logs do not need it); one set of 48 known logs; four small models; three runs each.
